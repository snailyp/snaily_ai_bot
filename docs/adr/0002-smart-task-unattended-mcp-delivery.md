# 智能任务允许无人值守的 MCP 调用与自动投递

此前任务模型请求不开放 MCP 工具，管理员推送中的 AI 产出也必须经管理员采用才能发布。智能任务有意打破这两条原则：任务运行在后台以系统身份调用该任务勾选的 MCP 服务器，并把结果不经人工审核直接投递到任务定义中固定的收件目标。替代的把关措施有四条：
- 按任务设置服务器白名单；
- MCP 服务器配置中的"允许后台任务使用"开关，默认关闭；
- 收件目标写死在任务定义中，AI 无法改写；
- 每个任务各自设置轮数、调用次数与超时上限。

不采用"每次运行先出候选、由管理员审核"的方案，因为定期简报与条件通知的价值在于及时、无需人工参与。代价是：模型的错误或被工具结果中的注入内容误导的输出会被直接发出，只能事后在运行记录中追查。

投递复用 ADR 0001 的事务日志与"结果不明不自动重发"规则，不另建投递机制。任务运行及投递安排在同一 SQLite 事务内封存，避免跨存储交接时重复发送；智能任务的投递与配图由运行记录统一保留，不按管理员推送的三天规则独立清理。
