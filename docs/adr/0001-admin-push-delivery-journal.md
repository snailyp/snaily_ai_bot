# 管理员推送使用事务日志与私有素材存储

管理员推送必须跨重启保留草稿、冻结的发布内容以及逐目标、逐部分的投递结果，并在编辑、执行、重试和素材清理之间作原子判定。因此使用 `data/admin_push/` 中的 SQLite 事务日志与独立图片文件，而不复用可选 Redis 配置、无事务的聊天 JSON 或会过期清理的会话图片。该选择服务于现有单实例、Web 线程与机器人事件循环并存的部署，不引入外部队列或多实例协调。

发送前先持久记录在途尝试，收到 Telegram 回执后再封存成功。数据库事务无法与 Telegram 的外部请求组成一个原子事务，因此请求已送达但回执未落盘的窗口明确记为「投递结果不明」，不自动重发，也不宣称恰好一次投递；这是为避免重复通知而接受需要管理员人工核实的取舍。
