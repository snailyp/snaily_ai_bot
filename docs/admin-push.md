# 管理员推送使用说明

在 Web 控制台选择 **管理员推送**。功能沿用 Web 登录权限，不依赖 Telegram 群管理员身份；不会自动向所有用户或群广播。需求规格见 [Issue #1](https://github.com/snailyp/snaily_ai_bot/issues/1)。

## 创作与保存

1. 输入正文，或直接选择配图。支持纯文字、纯图片、图文组合。
2. 可选用任务模型「润色文案」「扩写文案」，选择口吻，并补充事实素材与表达要求。结果只是候选，点击采用后才替换正文。
3. 上传 JPEG、PNG、静态 WebP，单张不超过 10 MB；或填写绘图描述、手动生成候选图。也可先让任务模型根据正文构思描述，再确认绘图。
4. 每次生成一张图片；明确采用后加入配图。最多4张，可混用、调整顺序、删除和替换。满4张仍可生成候选用于替换。
5. 点击 **保存草稿** 后才会持久保存。刷新后可从「草稿」列表继续编辑。未保存编辑不会变成永久隐藏草稿。

润色和扩写都不应编造未经提供的事实或承诺。发布前仍需管理员核实模型内容。创作不读取聊天会话历史，发布也不写入聊天上下文。

## 预览、试发与正式发布

- 正式目标手动填写聊天 ID 或 `@channel`，多个用英文逗号分隔；可显式导入已保存的热点目标，不会默认选中。
- 短正文放在图片说明中，多图组成相册；长正文先分段发送，再发图片。预览展示实际发送计划，不截断正文。
- 若超长连续空白会形成 Telegram 不接受的纯空白消息，预览会提示调整，不会偷偷删去内容或在发送时反复重试。
- **独立试发** 只发送到明确填写的单个测试目标，不消费正式预览，也不改变正式目标、时间或草稿。
- 正式确认后，已保存草稿转为任务。「已接受」只表示任务已持久保存，请在「任务记录」查看实际投递结果。
- 修改正文、图片、目标或时间后必须重新预览；预览也有有效期。如果定时时间已过去，必须重新选择时间并预览。
- 多个页面同时编辑时，旧页面不能静默覆盖或发送旧版本。遇到版本冲突，请刷新列表并核对最新内容。

## 定时与恢复

时间统一使用 **北京时间 `Asia/Shanghai`**，不随浏览器或服务器时区改变。只支持一次性定时，不支持周期发布。

待发送任务可以编辑后重新确认或取消；开始执行后不可修改/取消，即使任务后来因重试重新排队也一样。编辑页面不会暂停已经确认的原排程。

服务恢复时：

- 尚未开始的定时任务，延误不超过30分钟会补发；超过则记为「已错过」，不自动发送。
- 已开始任务根据逐部分日志恢复：已确认成功不重发；请求可能发出但没有明确回执的部分记为「结果不明」。
- 未完成的 AI 创作记为中断，不自动再次消耗模型额度。

## 失败、不明与重试

每个目标、每个消息部分分别记录结果；相册是一次请求，保存所有图片消息的回执。某个目标失败不影响其他目标。

- **失败**：明确被 Telegram 拒绝，或可确定请求尚未发出。可手动重试选中的失败部分。
- **结果不明**：例如请求超时，Telegram 可能已经接收。不会自动重发，请人工核实，避免重复通知。
- **未尝试**：前面的部分失败或不明，尚未继续发送。重试明确失败的前置部分成功后，可能继续首次发送这些部分；确认界面会说明范围。

不会自动撤回已经送达的内容。若需要更改已开始任务的内容，使用 **复制为草稿** 创建新的发布安排。

## 保存与清理

| 对象 | 保留时间 |
| --- | --- |
| 已保存草稿、待发送/发送中任务及引用配图 | 不自动到期 |
| 结束任务与不再被其他对象引用的配图 | 3天 |
| 未采用候选、未保存临时上传 | 24小时 |

执行过的任务从最后一次执行结束计算3天；取消、已错过的任务从进入对应状态计算。记录中显示清理时间。

复制为草稿会建立独立的配图引用，源任务到期不会破坏复制后的草稿。删除后台记录不撤回 Telegram 消息。为防止迟到的重复提交再次发布，清理后可保留不含正文/配图的操作标识摘要。

## 部署与排障

- 数据库和素材位于工作目录下的 `data/admin_push/`，不放入公开的静态目录。
- 使用仓库 Compose 时，现有 `./data:/app/data` 挂载覆盖这部分数据。其他部署方式必须挂载持久存储；临时文件系统不能保证重新部署后恢复。
- 采用现有单实例运行方式；不要用多个独立 bot 实例共享本功能存储。备份或迁移时先停止实例，并整体保留数据库和图片目录。
- 安装 `requirements.txt`，包含用于实际图片解码的 Pillow。生成图如果返回 URL，会在采用前安全下载并保存；拒绝内网地址、重定向、超限文件或损坏图片。
- 「运行时未就绪」时可保存草稿，但不能提交创作或发送。正常启动应使用项目标准机器人启动器；独立启动 Web 不会启动 Telegram 投递。
- API 返回版本冲突/过期时重新核对内容，不要绕开预览确认；网络失败后先查看任务记录，再决定是否重试。
